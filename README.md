# ai-methods-1-2026

General repository for **AI Methods I: Machine Learning for the Built Environment** (MaAI01, Term 1, IAAC).

It contains the lecture notebooks for each day of the course and links every student submission through **git submodules**. Each student keeps their work in their own repository inside the [iaac-maai](https://github.com/iaac-maai) organization, and this repository only points to it. This avoids conflicts with branches and version control: nobody pushes to this repository except the course maintainers.

## 1. Repository structure

```
ai-methods-1-2026/
├── Day_1/
│   ├── docs/                  # lecture notebook, data/ and figures/ folders
│   └── submissions/           # student submissions (submodules)
├── Day_2/                     # same structure as Day_1
├── Day_3/
├── Day_4/
├── hackathon/
│   ├── docs/                  # hackathon cheat sheet and data/
│   └── submissions/           # team submissions (submodules)
├── readme_resources/          # images used in this README
├── .gitignore                 # files git must NOT track (venv, data, documents...)
├── .gitmodules                # list of linked submission repositories
├── requirements.txt           # Python packages (and versions) used in the course
├── LICENSE                    # MIT license
└── README.md                  # this file
```

| Folder | Notebook | Topic |
|---|---|---|
| `Day_1/docs` | `data_cleaning_and_EDA.ipynb` | Data cleaning and Exploratory Data Analysis |
| `Day_2/docs` | `application_of_supervised_learning.ipynb` | Supervised learning |
| `Day_3/docs` | `application_of_unsupervised_learning.ipynb` | Unsupervised learning |
| `Day_4/docs` | `Introduction_to_nn_and_cv.ipynb` | Introduction to neural networks and computer vision |
| `hackathon/docs` | `hackathon_cheat_sheet.ipynb` | Hackathon reference |

> Notebooks are published on the day of each lecture. Until then they show an "under construction" message.

### What each special file does

| File | Purpose |
|---|---|
| `.gitignore` | Tells git which files to ignore. Here it excludes the virtual environment (`.venv/`), data files (`*.csv`, `*.png`, `*.jpg`, `*.jpeg`) and documents (`*.pdf`, `*.docx`). Datasets are downloaded from Kaggle by the notebooks, so they never need to be committed. |
| `.gitmodules` | Generated by `git submodule add`. Each entry links a folder in `submissions/` to a student repository. **Students do not edit this file.** |
| `requirements.txt` | Pinned versions of every package used in the notebooks, so everyone runs the same code with the same results. |
| `.gitkeep` | Empty placeholder files. Git does not track empty folders, so `.gitkeep` keeps folders like `data/` and `submissions/` in the repository. |

## 2. Before you start

Install these once:

| Tool | Download | Check it works |
|---|---|---|
| Git | <https://git-scm.com/downloads> | `git --version` |
| GitHub CLI (optional, recommended) | <https://cli.github.com> | `gh --version` |
| Python **3.12** *or* Anaconda/Miniconda | <https://www.python.org/downloads> / <https://www.anaconda.com/download> | `python --version` / `conda --version` |

Then:

1. Create a GitHub account (if you do not have one) and **accept the invitation to the [iaac-maai](https://github.com/iaac-maai) organization**. You need it to create your submission repository.
2. Tell git who you are (use the same email as your GitHub account):

   ```bash
   git config --global user.name "Your Name"

   ```

3. If you use the GitHub CLI, log in once:

   ```bash
   gh auth login
   ```

   Choose *GitHub.com* → *HTTPS* → *Login with a web browser*.

## 3. Clone the repository

Go to the folder where you keep your course work, then use **one** of the options below.

**Option A: git**

```bash
git clone --recurse-submodules https://github.com/iaac-maai/ai-methods-1-2026.git
cd ai-methods-1-2026
```

**Option B: GitHub CLI**

```bash
gh repo clone iaac-maai/ai-methods-1-2026 -- --recurse-submodules
cd ai-methods-1-2026
```

`--recurse-submodules` also downloads the linked submissions. If you cloned without it, run:

```bash
git submodule update --init --recursive
```

## 4. Keep it up to date (pull)

New notebooks are pushed on each lecture day. To get them:

```bash
cd ai-methods-1-2026
git pull --recurse-submodules
git submodule update --init --recursive
```

With the GitHub CLI you can sync in one step:

```bash
gh repo sync
git submodule update --init --recursive
```

> ⚠️ **Do not edit the lecture notebooks inside this repository.** If you change a file that we also update, `git pull` will fail with a conflict. Copy the notebook into **your own submission repository** (section 6) and work there.
>
> If you already edited something and the pull fails, you can discard your local changes with `git restore .` (this deletes your edits, so copy them somewhere else first) or keep them aside with `git stash`.

## 5. Set up the Python environment

A **virtual environment** is an isolated Python installation for one project. It keeps the course packages separate from the rest of your computer and makes sure everyone uses the same versions from `requirements.txt`.

Choose **one** option: `venv` (plain Python) or `conda` (Anaconda/Miniconda). Run the commands from the root of the repository.

### Option A: Python `venv`

**1. Create the environment** (only once):

```bash
# macOS / Linux
python3 -m venv .venv

# Windows
python -m venv .venv
```

**2. Activate it** (every time you open a new terminal):

```bash
# macOS / Linux
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Windows (Command Prompt)
.venv\Scripts\activate.bat
```

Your prompt now starts with `(.venv)`.

> On Windows, if PowerShell blocks the script, run once:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

**3. Install the packages:**

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install ipykernel      # lets VS Code / Jupyter run notebooks with this environment
```

**4. Deactivate** when you are done: `deactivate`

### Option B: Anaconda / Miniconda

**1. Create the environment** (only once):

```bash
conda create -n ai-methods python=3.12
```

**2. Activate it** (every time you open a new terminal):

```bash
conda activate ai-methods
```

**3. Install the packages:**

```bash
pip install -r requirements.txt
pip install ipykernel
```

> Use `pip` (not `conda install`) for `requirements.txt`: the file pins exact pip versions, and some packages (like `kagglehub`) are not on the default conda channels.

**4. Deactivate** when you are done: `conda deactivate`

### Select the environment in VS Code

1. Open a notebook (`.ipynb`).
2. Click **Select Kernel** (top right) → **Python Environments**.
3. Pick `.venv` (Option A) or `ai-methods` (Option B).

### Datasets

The notebooks download their datasets from [Kaggle](https://www.kaggle.com) with `kagglehub` and save them in the local `data/` folder. These files are ignored by git, so you need to run the download cell once on your computer.

## 6. Create your submission repository

Each submission is a **separate repository inside the iaac-maai organization**, not on your personal profile. Repositories on personal profiles will not be linked.

### 6.1 Create the repository

**Option A: GitHub CLI** (creates it on GitHub and clones it in one step)

```bash
gh repo create iaac-maai/<repo-name> --public --clone --add-readme --gitignore Python
cd <repo-name>
```

**Option B: GitHub website + git**

1. Go to <https://github.com/iaac-maai> → **New repository**.
2. Set **Owner** to `iaac-maai` (not your username) and write the repository name.
3. Tick **Add a README file** and choose the **Python** `.gitignore` template.
4. Click **Create repository**, then clone it:

   ```bash
   git clone https://github.com/iaac-maai/<repo-name>.git
   cd <repo-name>
   ```

> Create your submission repository **outside** the `ai-methods-1-2026` folder. A repository inside another repository is exactly what submodules are for, and the course maintainers are the ones who link it.

### 6.2 Recommended structure

```
<repo-name>/
├── data/
│   └── .gitkeep          # keeps the folder; datasets themselves are not committed
├── figures/
│   └── .gitkeep
├── notebook.ipynb        # your work (one or more notebooks)
├── .gitignore
├── requirements.txt
└── README.md
```

### 6.3 The files every submission needs

**`.gitignore`**: what git must not upload. Start from GitHub's Python template (section 6.1) and make sure it contains at least:

```gitignore
# virtual environments
.venv/
venv/
env/

# Jupyter
.ipynb_checkpoints/

# data and outputs (download them in the notebook instead)
*.csv
data/*
!data/.gitkeep

# OS files
.DS_Store
Thumbs.db

# secrets
.env
kaggle.json
```

> Never commit your virtual environment, large datasets or credentials (`kaggle.json`, API keys, `.env`). If a file is already tracked, `.gitignore` will not remove it: run `git rm --cached <file>` and commit.

**`requirements.txt`**: the packages your notebook needs. You can copy the course `requirements.txt`, or export the packages from your active environment:

```bash
pip freeze > requirements.txt
```

Then remove packages you did not use (e.g. `ipykernel`, `debugpy`) so the file stays short.

**`README.md`**: what someone needs to understand and run your work:

- Title, your name(s) and the day (or hackathon) it belongs to.
- **Use case**: what problem you are solving.
- **Dataset**: name, source (link) and a short description (the *dataset card* from Day 1).
- **How to run**: create the environment, `pip install -r requirements.txt`, open the notebook.
- **Results**: main findings, with a figure or two.

**Notebooks**: before committing, **Restart & Run All** to check that the notebook runs from top to bottom without errors, and keep the outputs so they are visible on GitHub.

### 6.4 Save and upload your work

```bash
git add .
git commit -m "Short description of what you did"
git push
```

Check `git status` before committing to make sure you are not adding data or the virtual environment.

## 7. Hand in your submission

1. Push your final version to the `main` branch **before the deadline**.
2. Send the repository URL (`https://github.com/iaac-maai/<repo-name>`) to the course maintainers.
3. The maintainers link it into `Day_N/submissions/` or `hackathon/submissions/` as a submodule. The course repository records the **exact commit** that was submitted, so later pushes do not change your submission unless the maintainers update the link.

## 8. Troubleshooting

| Problem | Fix |
|---|---|
| Submission folders are empty after cloning | `git submodule update --init --recursive` |
| `git pull` fails because of local changes | Copy your edits elsewhere, then `git restore .` (or `git stash`) and pull again |
| `ModuleNotFoundError` in a notebook | The notebook is using the wrong kernel: select `.venv` / `ai-methods` in VS Code, or activate the environment and run `pip install -r requirements.txt` |
| `python` is not found (Windows) | Reinstall Python and tick **Add python.exe to PATH**, or use `py` instead of `python` |
| Cannot create a repository in iaac-maai | Accept the organization invitation (check your email or <https://github.com/iaac-maai>) and ask the maintainers for permission |
| Pushed a large file or a secret by mistake | Contact the maintainers. Deleting it in a new commit does **not** remove it from the history |
